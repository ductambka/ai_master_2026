# Safe course reference service

This capstone sample turns the course principles into a small, dependency-free HTTP service. It is deliberately local and deterministic: it has no network tool, shell execution, model provider, database, authentication system, or production data path.

## Run

```bash
python -m service --host 127.0.0.1 --port 8080
curl -i http://127.0.0.1:8080/healthz
curl -sS -X POST http://127.0.0.1:8080/v1/tools/execute \
  -H 'Content-Type: application/json' \
  -d '{"tool":"course.lesson_summary","input":{"lesson_id":"L07"}}'
```

The only allowed tools are `course.echo` and `course.lesson_summary`. Unknown tools return HTTP 403. Requests are bounded to 64 KiB, inputs are validated, and every response includes `X-Request-ID` (accepted only from a restricted character set or generated by the service).

## Threat model and residual risk

- **Protected:** arbitrary command execution, arbitrary tool names, oversized request bodies, malformed JSON, and accidental secret exposure in structured logs.
- **Trust boundary:** the HTTP caller is untrusted. The in-process tool registry is trusted code and must remain reviewed source code.
- **Logging:** JSON records contain event, request ID, route, and tool metadata only. Secret-like keys and common token patterns are redacted before logging.
- **Residual risk:** this sample has no authentication, TLS, rate limiting, persistent audit store, multi-process isolation, or production-grade observability. Bind it to loopback or place it behind a hardened gateway for demonstrations only. Do not send real credentials, personal data, or production requests.
- **Rollback:** stop the process and revert to the previous source/image version. No persistent state is written by this service.

## Verification

```bash
pytest -q
python -m compileall service
```

The integration tests exercise health/readiness, request IDs, an allowlisted tool, schema rejection, forbidden tools, and log redaction.
